# Rootine 管理者向け運用マニュアル

対象：システム管理者・運用引き継ぎ担当者  
作成日：2026年10月28日  
確認範囲：作業フォルダー内の現行ソースコード。稼働環境の設定値・接続状況は未確認。

## 1. 管理者の役割

管理者は「管理者用設定」画面で、全体設定、店舗別の決済方法、店舗とユーザーの対応状況、データベースの件数を確認します。注文受付や日報などの日常業務は、対象店舗のアカウントで行います。

| 管理する項目 | 適用範囲 | 操作・保存方法 |
| --- | --- | --- |
| キャンセル用パスワード | システム全体 | 変更後に「設定を保存する」 |
| 作成可能な店舗数上限 | システム全体 | 変更後に「設定を保存する」 |
| 決済方法 | 選択した店舗 | 追加・削除後に「決済方法を保存する」 |
| 店舗管理 | 一覧に表示されるユーザー・店舗 | 確認のみ。「再読み込み」で更新 |
| データベース管理 | 接続中のDB | コレクション名と件数を確認 |
| テストデータのリセット | 対象テストDB内の全店舗 | 条件を満たすテスト環境でのみ表示 |

**全体設定と決済方法の保存は別操作です。** 一方の保存ボタンだけでは、もう一方の変更は保存されません。

## 2. ログイン・ログアウト

1. 利用環境のログイン画面（`/login`）を開きます。
2. 管理者権限のあるアカウントのIDとパスワードを入力します。
3. 「ログイン」を押し、「管理者用設定」（`/admin`）が表示されることを確認します。
4. 作業終了後は、画面下部の「ログアウト」を押します。

店舗アカウントでは注文画面に移動します。管理者画面を開けない場合は、利用アカウントと権限を確認してください。管理者アカウントの発行・権限変更は、この画面には用意されていません。システム保守担当者へ依頼します。

## 3. 初回運用前の確認

- 利用環境のURLと、管理者・店舗アカウントの使い分けを確認する。
- 「店舗管理」で店舗名・ユーザーID・店舗IDの対応を確認する。
- キャンセル用パスワードを確認し、必要に応じて変更する。
- システム全体の店舗数上限を確認する。
- 各店舗の決済方法を設定し、店舗担当者に会計画面の表示を確認してもらう。
- 障害時の連絡先とデータ保全方法を運用担当者間で決める。

## 4. 全体設定を変更する

### キャンセル用パスワード

注文履歴画面で注文のキャンセル処理を進める際に使用する、システム共通のパスワードです。管理者のログインパスワードとは用途が異なります。

1. 「キャンセル用パスワード」に新しい値を入力します。
2. 同時に保存される「作成可能な店舗数上限」が意図した値であることを確認します。
3. 「設定を保存する」を押します。
4. 「管理者設定を保存しました」の表示を確認します。
5. 再読み込みして設定を確認し、キャンセル処理を担当する人へ変更を共有します。

空白だけの値は保存できません。前後の空白を除いて1～80文字です。管理者画面では入力値が伏せ字にならないため、画面共有や資料への写り込みに注意してください。ソース上の初期値は `0000` ですが、既存環境には変更済みの値や移行した設定が適用されている場合があります。

### 作成可能な店舗数上限

システム全体で作成できる店舗数を指定します。1～9,999の整数を入力し、「設定を保存する」で保存します。

- 上限に達すると、新規登録などによる店舗作成が拒否されます。
- この上限は、1人のユーザーが持てる店舗数とは別です。現行の店舗作成処理は1ユーザー1店舗です。
- 上限の値を下げても、既存店舗を削除する処理は実行されません。

## 5. 店舗ごとの決済方法を設定する

1. 「決済方法の設定」で店舗を選びます。店舗名と括弧内の所有ユーザーIDを確認します。
2. 設定済み決済方法の読み込みが完了するまで待ちます。
3. 追加する場合は名称を入力して「追加」を押します。削除する場合は名称横の「x」を押します。
4. 一覧を確認し、「決済方法を保存する」を押します。
5. 「決済方法を保存しました」の表示を確認します。
6. 店舗を選択し直して保存内容を確認し、対象店舗の端末も再読み込みして表示を確認します。

設定できる名称は1件につき前後の空白を除いて1～80文字、最大30件です。同じ名称は重複登録されません。追加・削除した段階では未保存で、保存前に店舗を切り替えると編集内容は失われます。

空の一覧も保存できるため、全件を削除するときは会計業務への影響を確認してください。この設定はアプリ内の決済方法の名称を管理する機能です。決済サービスとの契約や端末設定は、別途確認します。

## 6. 店舗管理の見方

「再読み込み」を押すと一覧が更新されます。店舗名だけで判断せず、ユーザーIDと店舗IDを合わせて確認してください。

| 表示 | 意味・確認すること |
| --- | --- |
| ユーザー | 一覧の対象となるユーザー数 |
| 店舗 | 一覧の対象となる店舗数 |
| 要整理 | 所有店舗または登録済み店舗IDが複数あるユーザー数 |
| active | ユーザー情報に保存された利用店舗IDと一致する店舗 |
| 店舗がありません | 該当ユーザーを所有者とする店舗が一覧にない状態 |
| 所有ユーザーが存在しない店舗 | 対応する所有ユーザーが一覧に見つからない店舗 |

「要整理」は全種類の不整合を数える表示ではありません。0件でも、店舗がないユーザーや所有ユーザー不在の警告を確認します。また、この一覧ではIDが `admin` のユーザーと、所有者またはメンバーに `admin` を含む店舗が除かれるため、DB全体の件数とは一致しない場合があります。

不整合を見つけたら、対象ユーザーID・店舗ID・表示内容を記録し、保守担当者へ連絡します。この画面には店舗の編集・削除機能はありません。旧来の店舗データ自動整理機能も廃止されています。

## 7. データベースの件数を確認する

「データベース管理」には、接続中のDBのコレクション名と保存件数が表示されます。「再読み込み」で更新します。

件数は売上金額や注文の正常性を示すものではありません。売上や注文内容の確認は、対象店舗の注文履歴・日報で行います。店舗の日報画面には「全注文CSV」がありますが、これはDB全体のバックアップではありません。

一覧が空でも、取得失敗の場合があるため、直ちにデータ消失と判断しないでください。再ログイン・再読み込み後も同じ場合は、保守担当者に取得状況と接続先の確認を依頼します。

## 8. テストデータのリセット（テスト環境専用）

**この操作は対象DB内の全店舗に影響します。店舗を選択して実行する機能ではありません。** 日常の営業終了処理には使用しません。

### 対象と影響

| 項目 | リセット後 |
| --- | --- |
| 注文履歴 | 全店舗分を削除 |
| 会計見積もり情報 | 全件を削除 |
| 整理券番号 | 発行済み番号を0に戻す |
| 待機商品数の設定値 | 0に戻す |
| 本日の受付 | 全店舗で停止 |
| 商品・アカウント・店舗 | 保持 |
| その他の設定 | 保持 |

画面に復元ボタンはありません。また、注文・会計関連のすべてのコレクションを消去する機能ではなく、上表の対象をリセットする処理です。

### 操作手順

1. 「対象DB」の名称を確認し、必要なテスト記録を保存します。
2. 利用中の担当者に全店舗への影響を伝え、テスト操作を止めます。
3. 「ログイン中の管理者のパスワード」を入力します。キャンセル用パスワードは使用しません。
4. 「テストデータを削除することを確認しました」にチェックします。
5. 「パスワードを確認してリセット」を押し、完了結果を確認します。
6. DB件数を再読み込みし、各店舗の状態を確認します。
7. テストを再開する店舗のアカウントで日報画面を開き、「営業を再開する」を押します。
8. 各端末を再読み込みしてからテストを再開します。

「結果を確認できません」と表示された場合は、結果が不明な状態です。連続実行せず、保守担当者にDBの状態を確認してもらいます。

### 表示条件（保守担当者向け）

次の条件を満たした環境に限り利用できます。表示されないこと自体は異常ではありません。

- `ENABLE_TEST_DATA_RESET` が `true`。
- Vercelのプレビュー環境、またはVercel外のローカル開発環境。
- 本番環境ではない。
- `MONGODB_DB` が `test_` で始まり、続く部分が英数字・ハイフン・アンダースコアで構成される。

実行時には管理者権限、管理者パスワード、確認チェック、および実際の接続先DB名との一致も検証されます。

## 9. 困ったときの対応

| 状況 | 確認・対応 |
| --- | --- |
| ログイン画面に戻る | 再ログインしてから操作する |
| 管理者画面ではなく注文画面が開く | 管理者権限のあるアカウントか確認する |
| 設定を保存できない | 上限の範囲・整数指定、パスワードの空欄・文字数を確認する |
| 決済方法を取得できない | 店舗を選択し直す。続く場合は店舗IDとエラー内容を記録する |
| 決済方法を保存できない | 名称の空欄・文字数・件数を確認し、保存結果を確認する |
| 店舗数上限で登録できない | 現在の店舗数と設定上限を確認する |
| 店舗情報・DB一覧が更新されない | 再ログイン後に再読み込みし、改善しなければ保守担当者へ連絡する |
| リセット後に注文を受け付けられない | 店舗アカウントの日報で営業を再開し、端末を再読み込みする |

問い合わせ時は、発生日時（日本時間）、環境URL、画面名、対象店舗ID、操作手順、表示されたメッセージを伝えます。パスワードは記載しません。

## 10. 日常確認と引き継ぎ

**運用開始前：** 店舗の対応状況、必要な決済方法、店舗側の受付状態を確認します。  
**設定変更時：** 変更前後の値・対象店舗・担当者・日時を記録し、保存成功と再読み込み後の値を確認します。パスワードそのものは変更記録に残しません。  
**作業終了時：** 未解決の警告と問い合わせを引き継ぎ、管理者画面からログアウトします。

| 引き継ぎ項目 | 記入欄 |
| --- | --- |
| 利用環境・URL |  |
| 管理責任者・保守連絡先 |  |
| 対象店舗名・店舗ID |  |
| 設定変更の日時・担当者・内容 |  |
| 未解決事項・次の対応 |  |
