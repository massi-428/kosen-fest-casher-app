# 9月12日発表向け：実装と検証記録

## 注文・精算の運用

- 注文確定で会計済み。active / pending / completed が売上対象、cancelled は対象外。保留・復帰・提供完了では売上が変わらない。
- 日報・商品別・決済別・全注文CSVは日本時間の注文受付日で、変更後の金額を計上する。別日の変更・取消も受付日の売上を更新する。精算日の現金出納帳ではない。
- 全注文CSVの売上計上額（明細）の合計を日報と比較する。キャンセルを残し売上対象外と明示する。注文合計は明細ごとに繰り返す参考値。精算履歴を売上へ再加算しない。
- 編集・全取消は、先にサーバーで対象注文・金額を確定する。単一注文の更新でロックと操作を保存し、他の編集・完了・復帰・取消を拒否する。注文更新と精算履歴は一度の原子的更新で保存する。
- 「受け渡しへ進む」は担当者一人だけが開始する。その後に一度だけ実際の徴収・返金を行い、確認して記録する。外部決済は自動実行しない。
- 受け渡し前は中止できる。受け渡し開始後は時間切れで解除せず、履歴の「未完了の精算」から担当者が確認して記録を完了する。開始ボタンを押しただけで実際には未実施の場合も、担当者間で確認が必要。開始後の強制解除機能は設けていない。
- 応答が不明な場合は操作IDから結果確認する。受け渡しを繰り返さない。再読み込み後もサーバーに未完了操作が残る。初回の預り金・釣銭は保持し、追加徴収分を別の履歴へ記録する。再開時の預り金は担当者が実際の受領額を確認して入力する。
- 全取消は現在の注文総額だけ返金する。例：初回1,000円→差額返金500円→全取消500円。二重返金を計上しない。差額ゼロの編集は受け渡し不要。
- 旧注文のrevision・精算履歴欠落に対応する。受付済み明細の価格を維持し、新規明細には現在価格を使う。
- 整理券返却は注文IDとrevisionで現在のactive/pendingだけを更新する。完了取消は番号再利用時に拒否し、完了日時を消して再完了時に記録し直す。

## 新規会計・カート・検索

- 会計前にサーバーで商品・オプション・売り切れと価格を確認する。金額変更時は新金額を提示して再確認する。
- 確認済みの見積もりは内容・価格・会計設定を固定する。その後の価格・売り切れ変更でも、この会計の提示金額を保証する。見積もりに自動期限はない。商品在庫数や整理券の物理的な取り置きではない。
- 注文送信前に内容・支払情報・操作IDを店舗／ユーザー単位で一時保存する。結果不明では編集を止め、同じIDの結果確認・再試行で復旧する。成功後は消去する。
- 保存不可の環境では案内を表示する。結果不明の間は画面を閉じない。別端末にローカルカートは同期されない。
- 履歴は日本時間の今日を初期表示とし、日付・整理番号・状態をサーバー側で検索する。1ページ100件。時間帯別集計はその検索の全件（キャンセル除外）を対象にする。
- 初回失敗・読み込み中・検索結果なしを区別し、取得済みデータがある場合は最終成功時刻と古いデータである旨を示す。古い応答は最新検索を上書きしない。

- 実際の現金・外部決済、物理的な複数端末、実店舗ネットワーク切断は未検証。ブラウザーは同一マシンの二画面、障害は通信層の模擬。
- 膨大な注文数での性能試験、長時間運用、見積もり・操作履歴の自動整理は今回の対象外。未完了精算一覧は古いものから100件まで表示する。
- 同じブラウザーの同一ユーザー／店舗のカートは一つの保存領域を使う。複数タブで別々の新規カートを同時編集する運用は避ける。
